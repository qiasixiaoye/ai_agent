# 复杂工作流 · 输入模板（一句话 → 并行多工具 + 汇聚）

> 适用于「工作流生产」页的智能生成。生成器会在**选中 ≥2 个相互独立的工具**时，
> 自动产出**并行 fan-out → 汇聚(template-transform) → LLM → 收尾**的复杂图（而非串行链）。
> 因此「让输出复杂」的关键，是在输入里**并列地点出多个互不依赖的子任务**，每个子任务对应一个能力。

---

## 一、万能骨架（留白处填关键词即可）

```
我要做一个关于【主题/场景】的【交付物】。
已知条件：【参数1=具体值】、【参数2=具体值】、【参数3=具体值】。
请分别完成以下相互独立的子任务：
① 【子任务A】（对应能力 A）
② 【子任务B】（对应能力 B）
③ 【子任务C】（对应能力 C）
④ 【子任务D】（对应能力 D）
（可继续往下加 ⑤⑥…，子任务数 ≈ 并行分支数）
最后把以上全部结果整合成【最终交付物：中文报告 / 表格 / 计划 / PDF…】。
```

### 写法三原则（决定能否触发「并行 + 汇聚」）
1. **并列、互不依赖**：每个子任务都只依赖开头的「已知条件」，**不要写成"基于①的结果再做②"**——
   有先后依赖就退化成串行。用「分别 / 同时 / 并且」连接。
2. **给具体参数**：经纬度、日期、焦距、里程、冲煮方式等都给到数值/枚举值，工具参数才能填准
   （日期类即使不写，http 模式也会在生成时按当天算好）。
3. **末尾点"整合"**：一句"整合成…"对应自动生成的「汇聚节点 + LLM 汇总」。

> 子任务 0–1 个 → 串行简单图；**≥2 个独立子任务 → 并行复杂图**。想要更复杂就多列几条独立子任务。

## 二、关键词 → 能力 速查（留白词表）

| 你在留白里写的关键词 | 命中能力 | 需要的参数（建议在已知条件里给） |
|---|---|---|
| 银河 / 银心 升起时刻、方位 | `milkyway_rise` | 纬度、经度、日期 |
| 光污染 / Bortle 等级 | `light_pollution` | 纬度、经度 |
| 夜间云量 / 天气 | `cloud_cover` | 纬度、经度、日期 |
| 星空参数 / 500 法则 / 焦距 | `astrophoto_settings` | 焦距（mm） |
| 曝光建议 / 拍摄场景 | `exposure_advisor` | 场景（夜景/风光/人像…） |
| 联网搜索 / 查资料 / 推荐 | `web_search` | 关键词 |
| 找图 / 样张 / 配图 | `image_search` | 关键词 |
| 咖啡冲煮 / 手冲 / 意式配方 | `coffee_recipe` | 冲煮方式（pourover/espresso） |
| 咖啡风味 / 品鉴 | `coffee-tasting-notes`(skill) | 产地、烘焙度 |
| 摩旅 / 里程规划 / 骑行天数 | `moto_trip_planner` | 总里程（km） |
| 装备清单 / 打包清单 | `moto-gear-checklist`(skill) | 季节、天数 |
| 生成 PDF / 导出报告 | `pdf-generation`(skill) | （内容自动来自上游） |

> 同一**领域内的独立子工具越多，并行分支越多**。星空摄影是工具最密的领域（一次可拉 5–6 路并行）。

## 三、已测复杂样例（6 路并行，已验证导入 Dify）

输入：

```
周末去河北坝上（纬度41.8，经度116.9）拍银河，带24mm F1.4镜头、机身最高ISO6400。
请算出银河升起与最佳拍摄时段，评估当地光污染等级和夜间云量，按这支镜头给星空摄影参数，
再针对高原暗夜无光污染场景给曝光建议，最后整理成带时间表的中文拍摄计划。
```

生成结果（http 形态）：

```
                ┌─→ 银河升起 milkyway_rise ─┐
                ├─→ 光污染 light_pollution ─┤
开始(start) ────┼─→ 夜间云量 cloud_cover ───┼─→ 汇聚 ─→ LLM 汇总 ─→ 收尾
                ├─→ 星空参数 astrophoto ────┤  (template-       (answer/end)
                ├─→ 曝光建议 exposure ──────┤   transform 拼接)
                └─→ 计划汇总 astro_plan ────┘
```

* 节点类型：`start ×1 / http-request ×6 / template-transform ×1 / llm ×1 / answer(或 end) ×1`
* `start` fan-out = 6（真并行），6 路 fan-in 到 `aggregate` 汇聚节点
* 校验通过、导入 Dify success（`completed-with-warnings` 属正常 DSL 版本升级）

## 四、换领域怎么填（同骨架，不同留白）

* **相机选购**（跨域 3 路并行）：「联网搜索星空全画幅微单**推荐**，找几张代表机型**样张图**，
  整合成选购报告，并**生成 PDF**」→ `web_search + image_search + pdf-generation` 并行后汇总。
* **咖啡**（2 路）：「耶加雪菲日晒中浅烘焙，给 V60 **手冲配方**，并预测**风味品鉴**要点」
  → `coffee_recipe + coffee-tasting-notes`。
* **摩旅**（2 路）：「800km 川西摩旅夏季 5 天，做**里程天数规划**，并给**装备清单**」
  → `moto_trip_planner + moto-gear-checklist`。

> 形态选择：要可复现、参数准 → **HTTP**；要体现自主编排 → **Agent**（折叠成单 Agent 节点，不走并行图）。
> 应用形态：要多轮追问微调 → **多轮对话(chatflow)**；要跑一次出结果 → **单轮工作流(workflow)**。
> 注意：**并行 + 汇聚仅在 HTTP 形态**出现；Agent 形态是「单 Agent 节点挂多工具、由 LLM 自主调度」。
