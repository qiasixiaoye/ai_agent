# 企业外勤调研对话演示设计

## 目标

在现有对话工作台中交付一个可复现的企业级演示闭环。用户提出一次外勤调研需求后，系统自动路由到受限 Skill，调用只读工具形成建议，展示工具证据和记忆引用；对会产生外部影响的导出动作由后端强制要求二次确认。任何依赖不可用时，系统给出准确的降级说明，不伪造工具结果或权限状态。

## 演示查询

默认演示查询为：

> 我下周要去北京朝阳区做客户外勤调研。请结合天气和公共出行风险，给出上午/下午建议；我偏好中文回答、先给结论再给步骤。若需要导出含联系方式的行程审批单，请先向我确认。

这个查询同时覆盖：Skill 自动选择、三个只读能力、可写入偏好记忆、最终回答中的引用、需要确认的导出能力和统一 Trace。

## 架构与职责

### 1. 企业外勤调研 Skill

新增 `EnterpriseFieldResearchSkill`，只接受地点、日期范围和任务目标三个输入。它是一个编排边界，不拥有绕过权限检查的执行能力。Skill 元数据声明允许的工具集合：天气摘要、公共出行风险、外勤建议汇总。

Skill 将结构化工具结果组合为一份 `FieldResearchBrief`：上午建议、下午建议、已验证事实、限制说明和推荐的下一步。它不得把缺失结果补写为事实。

### 2. 只读工具与写入工具

新增或明确以下能力：

| 能力 | 类型 | 权限 | 输出 | 不可用时 |
| --- | --- | --- | --- | --- |
| `field_weather_summary` | Tool | READ_ONLY | 位置、日期、天气摘要、数据来源、获取时间 | 返回 `unavailable`，不推断天气 |
| `public_transit_risk` | Tool | READ_ONLY | 出行风险等级、原因、数据来源、获取时间 | 返回 `unavailable`，建议预留时间但不声称风险低 |
| `field_research_brief` | Tool | READ_ONLY | 聚合建议与证据索引 | 保留已有可验证结果和限制 |
| `export_trip_approval` | Tool | IRREVERSIBLE_WRITE | 审批单编号或导出结果 | 未确认时拒绝执行并返回确认要求 |

`export_trip_approval` 的执行仍须通过现有 `ToolGovernanceService`。前端携带的确认状态只是一种请求信号；后端必须基于工具权限级别和确认令牌再次判断。缺少确认令牌时不得生成文件或写入任何审批记录。

### 3. 记忆与引用

记忆候选只在本轮回答完成后评估。查询中的“偏好中文回答、先给结论再给步骤”会被识别为普通偏好；写入成功后返回带 `memoryId`、`type`、`content` 和 `status=written` 的事件。若被判断为敏感内容，则只产生待确认候选，绝不自动保存原文。

最终回答中只显示已经可用的引用：

- 工具引用：工具名、来源、获取时间和结果状态；
- 记忆引用：记忆类型、脱敏后的内容摘要和写入状态；
- 降级引用：能力名称与 `unavailable`/`blocked` 原因。

引用由后端统一事件生成；前端只渲染事件，不自行根据文案推断调用成功、权限通过或记忆已写入。

### 4. 对话工作台体验

在聊天输入区域提供“填入企业外勤演示”按钮，只填充上面的查询，不自动提交，确保用户仍能编辑地点和日期。提交后，当前会话的右侧检查器按时间顺序显示：路由结果、Skill、每个工具、每个证据、记忆写入结果和导出确认状态。

当系统请求导出时，回答和检查器显示“需确认”操作。确认按钮只发送一次带确认令牌的续执行请求；未确认、取消、令牌无效和已过期均呈现为 `blocked`，不会静默重试。

## 流程

```text
用户编辑并提交演示查询
  -> RequestOrchestrator 选择 ENTERPRISE_FIELD_RESEARCH Skill
  -> Skill 在白名单内依次调用 READ_ONLY 工具
  -> 每项结果发出 capability / evidence 事件
  -> 汇总并流式返回建议及引用
  -> 完成后 MemoryCandidatePipeline 写入非敏感偏好
  -> 如请求导出，ToolGovernanceService 拒绝未确认的写操作
  -> 前端展示确认入口；确认后的新请求才允许导出
  -> 全部事件使用同一 traceId，可在可观测性页面追溯
```

## 降级与安全契约

1. 工具超时、返回空数据或调用异常不影响主对话结束；回答明确列出不可用能力和仍可依据的事实。
2. 工具结果不得包含原始个人联系方式；导出工具接收的联系人字段只在确认后的服务端请求中处理，日志及引用只显示字段存在性和脱敏摘要。
3. 工具不在 Skill 白名单、参数缺失、工具禁用或确认令牌无效，均由后端返回 `blocked`。前端不得把 `blocked` 显示为成功。
4. 记忆仓储失败时主回答仍完成，事件状态为 `failed`，右侧允许用户进入记忆页重试；不会在前端伪造“已写入”。
5. 所有演示工具使用可追溯、确定性的演示数据适配层。后续接入真实天气或出行供应商时，需替换适配层并保留相同的证据、超时和降级契约；本期不把演示数据表述为实时公共数据。

## 验收标准

1. 点击“填入企业外勤演示”可看到完整但尚未发送的示例查询。
2. 提交后，事件序列至少包含：路由、Skill、两项只读工具、工具证据、最终回答、记忆状态。
3. 最终回答中每条工具结论均可对应到一个工具/证据引用；没有证据的结论必须标为建议或限制。
4. 偏好记忆写入后，右侧检查器和记忆页均显示同一条记录及相同状态。
5. 未确认的导出请求被后端拒绝，不能生成导出物；确认后才可成功，且 Trace 可区分两次请求。
6. 模拟天气、风险和记忆仓储失败时，主回答仍返回并包含对应的、非误导性的降级说明。
7. 单元测试覆盖白名单、确认、降级映射和引用事件；前端测试覆盖事件渲染和确认状态；构建与实际 HTTP/SSE 演示验证通过。

## 非目标

- 本期不接入真实企业审批系统、不发送邮件、不持久化真实联系人信息。
- 本期不承诺实时天气或公共出行数据；演示适配层的数据必须显式标示为演示数据。
- 本期不把 RAG 检索与记忆混为同一功能，知识库仍保持独立入口和独立引用。
